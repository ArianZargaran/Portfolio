# Safari and real-device checklist (M11a, first pass)

The box has no WebKit, so the code track can't verify these. Everything below is ready to run on Ari's Mac (Safari) and iPhone. It uses the shipped clips, with no deploy and no push. It takes about 10 minutes per device. Results replace the "untested" notes in PLAN v3.3 §4/§7 and `docs/hero-player.md`.

## 1. Run the probe page

From the repo root on the Mac (Node 20+):

```sh
npm run probe:safari                    # Mac only: loopback, http://localhost:4173/
PROBE_HOST=0.0.0.0 npm run probe:safari # also reachable from the iPhone on the same Wi-Fi
npm run probe:safari -- --check         # dry start: checks the clips/still, prints the URL, exits
npm run probe:safari -- --help          # usage
```

1. **Mac:** open `http://localhost:4173/` in Safari. Pick "Low Power Mode: off" and "Idle: 60 s", press **Run all checks**, and wait about 3 minutes. Keep the tab in front; the page reloads itself once at the end. Then press **Save**.
2. **iPhone:** open the `http://<mac-ip>:4173/` URL the server prints, in Safari. Run it once with Low Power Mode **off**, then turn it **on** (Settings → Battery) and run again. Press **Save** after each run.
3. Results land in `scripts/hero/safari-probe/results/run-*.json` on the Mac (gitignored). Send those files to Forge via Atlas. They hold only the browser's user agent and the measurements.
4. Stop the server with Ctrl-C.

The probe serves the shipped `app/scene/hero/media/*.mp4` with HTTP Range (Safari needs 206 responses for `<video>`) and the laptop still. A second port (+1) acts as a cross-origin host, with and without `Timing-Allow-Origin`. `?cache=reval` answers repeat loads with 304s, and `GET /clips` lists the shipped clip ids (`typing`, `nod.k180`, `s1a.k0`…`s1a.k180` and `t6.k0`…`t6.k180`). The codec and autoplay checks load the first action clip, the warm check holds what the player's pool can (`typing`, `nod.k180` and one S1a variant), and the S1a cut-in check loads every S1a variant. T6 has no probe row of its own: its enter window is two frames (f+0, f+1), so the S1a one-frame row is the stricter test of the same priming path.

## 2. What it measures and what decides

| 2   | iOS `muted playsinline` autoplay    | `autoplay.mutedPlaysinline`                                                  | `ok` with Low Power Mode off. Confirm there's no broken or black box                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 3   | `transferSize`, first load          | `timing.sameOriginFirstLoad`, `timing.navigation`, `timing.gateOnFirstVisit` | Non-zero on a same-origin first load, **and** `timing.sameOriginFirstLoad.gate` and `timing.navigation.gate` must both read `sample` (the gate's rule accepts a genuine first download). The probe sums this up in `timing.gateOnFirstVisit` (and `summary.gateOnFirstVisit`): **pass** if it starts with `ok`. `PROBLEM` means Safari reports a genuine download in a shape the gate rejects, so every Safari visit would start frozen and never store a verdict: send the file to Forge.                                                                                                                                                                                                                                                                                                                          |
| 4   | `transferSize`, cached              | `timing.cachedReload`                                                        | 0 expected. | 4b  | Cache-hit shapes (gate fix)         | `cacheHit.immutable`, `cacheHit.revalidate`, `cacheHit.gateOnRepeatVisit`    | The still is loaded twice in the page and once after the reload, as `?cache=1` (immutable) and `?cache=reval` (no-cache + ETag, so a repeat is a 304). Each entry records `transferSize`, `encodedBodySize`, `decodedBodySize`, `responseStatus`, `durationMs` and `gate` (the gate's own rule: `sample` or `cache hit -> inconclusive`). **Pass:** `gateOnRepeatVisit` starts with `ok`. `summary.allOk` is `true` only when this and row 3 (`gateOnFirstVisit`) both pass. If it says `PROBLEM`, Safari reports a cache hit in a shape the gate reads as a download: send the file to Forge                                                                                                                                                                                                                       |
| 5   | Cross-origin without / with TAO     | `timing.crossOriginNoTAO`, `crossOriginWithTAO`                              | 0 without TAO, non-zero with it. | 6   | Connection API                      | `env.connectionApi`                                                          | `false` on Safari, so the gate always takes the throughput path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## 3. By hand on the real site (after a local build, Mac Safari)

Run `npm run build && PORT=3150 node scripts/serve.mjs`, then open `http://localhost:3150/` in Safari at a laptop-width window (≥ 1025 px):

- [ ] The still paints first; the hero fades in over it after load. There's no seam at the feathered edge.
- [ ] `document.documentElement.dataset.heroGate` (Develop → Show JavaScript Console) reads `play:throughput-ok` on a first visit. On a reload it reads `play:stored`, the remembered verdict, because cached files read as cache hits (transferSize 0, encodedBodySize 0 or headers only).
- [ ] With Develop → Network → throttling at 3G or "Edge" on a fresh profile (clear website data), it reads `still:throughput-slow`, and no `.mp4` request appears in the Network tab.
- [ ] After clearing website data and with the cache served (Disable Caches off, second load), if nothing is measurable it reads `frozen:inconclusive`: the scene is paused, and Enter or Space on the focused scene plays it (a click does not).
- [ ] Clicking or tapping anywhere on the playing scene (window, wall, Ari's body over the video, floor; single and double click) never pauses it, and no caption or pause control appears. Clicking a hotspot still opens its page.
- [ ] Esc freezes instantly; `localStorage["hero:frozen"]` reads `v2:keyboard`; reloading stays frozen with no `.mp4` or `hero-*.js` requests. Tab to the scene and press Enter: it plays and the key is removed.
- [ ] Migration: in the console run `localStorage.setItem("hero:frozen","1")` (a freeze saved by the old click), reload: the scene plays and the key is gone. Run `localStorage.setItem("hero:frozen","v2:keyboard")`, reload: it stays frozen (still only, no media).
- [ ] Hovering the poster requests exactly one `s1a.k<join>.*.mp4` (the next join's variant) after the 250 ms dwell, and the glance-up cuts in on that join; then hovering the headphones (on Ari's head) within 10 s requests `nod.*.mp4` and exactly one `t6.k<join>.*.mp4` (Network tab): the speaker groove cuts in on that join and the nod follows at the first f180 after it. Nothing is requested before the dwell, and no `s1b`/`t2` file ever.
- [ ] Hovering the headphones alone (no poster first), and Tab-focusing them, each request exactly one `t6.k<join>.*.mp4` and no `nod.*.mp4`; the groove cuts in on that join with no hover hint or pause control appearing.
- [ ] Hover the poster again (move away and back) several times during the next 30 s: no new `s1a.*.mp4` request appears (the glance is in its cooldown). After 30 s the next hover requests one variant again.
- [ ] Leave the tab for 60 s and come back: no black frame on the next cut.
